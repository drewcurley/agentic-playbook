# T-003 — Workspace model + contracts/grounding upgrades (this PR)

## Description
Delivers two upgrades to the starter itself, on branch `feat/workspace-model`:
1. **Contracts + Grounding & Completeness Protocol** — a Tier 1 `contracts.md` (exhaustive code-grounded inventory), the § 6.0 protocol so docs are verified against real code, promotion of `api.md`/`data-model.md` to Tier 1, and a regression-safety commit gate (§ 7, § 8).
2. **Workspace model** — the fork can serve as a shared playbook governing one project across multiple repos: `workspace.manifest.md`, `docs/integration-map.md`, `scripts/setup-workspace.sh`, session-start workspace detection (§ 0 Step 0), § 6.5, cross-repo regression-safety, and the upstream-sync path (§ 7).

**Persona:** a team (and its AI agents) running one product across several repos (e.g. `web` / `api` / `infra`) that cannot merge into a monorepo right now, and wants AI to work across all of them and make changes trusted not to break a sibling.

## Acceptance criteria
- [x] `scripts/setup-workspace.sh` installs hooks into the playbook + every manifest repo, **verifies** `core.hooksPath` is actually set per repo, and rejects unsafe directory names (`..`, `/`, `~`, glob chars). Idempotent.
- [x] The script's guards are covered by an automated fixture test (`scripts/test/test-setup-workspace.sh`, 14 assertions: traversal/glob/absolute/tilde rejected + no out-of-bounds write, missing-repo reported, valid-repo governed & verified, placeholder no-op, idempotent re-run, no literal `\n`). Test + `shellcheck` run in CI (`.github/workflows/checks.yml` `scripts` job).
- [x] Single-repo behavior is unchanged: a repo with no `workspace.manifest.md` runs exactly as before; running the script with placeholder manifest is a safe no-op (asserted in the fixture test).
- [x] `docs/integration-map.md` template covers APIs (+auth, +version/window), events (+version, +idempotency, +old-schema tolerance), shared env/config, shared stores (shape-contract + write-exclusivity + expand/migrate/contract), derived data, shared packages, and cross-cutting invariants; names its own staleness as a review-enforced (not mechanical) risk.
- [x] `AGENTS.md` distinguishes mechanically-enforced from review-enforced hard gates (§ 8).
- [x] All 9 agents sign off (full cycle + 7 lenses ran; all PASS / PASS WITH ITEMS — see `docs/reviews/feat-workspace-model/final.md`).
- [x] ADR recorded for the workspace-model decision and its per-repo-enforcement trade-offs (`docs/decisions/0001-multi-repo-workspace-model.md`).

## Out of scope (tracked as follow-ups)
- An end-to-end demonstration that an agent in repo A surfaces repo B as blast radius from the integration map (Analyst suggestion) — belongs in a fork with real repos, not the stack-neutral starter.
- `setup-workspace.sh` also propagating `checks.yml` + the PR template into each repo, and a `--strict` exit code (DevOps suggestions) — sensible, but additive; tracked for a follow-up so this PR stays reviewable.
- Hook-version drift detection / stamp after upstream-sync (Architect suggestion).
- Secret-scan coverage for GCP service-account keys / high-entropy strings (Architect suggestion).

## Risks / dependencies
- Hooks are per-repo and cross-repo gates are review-enforced — see `AGENTS.md` § 6.5 "Honest limits" and § 8.
