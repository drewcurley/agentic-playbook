# T-009.3 — Acceptance-criterion IDs traced to passing tests

## Description
The Test Engineer redline "every acceptance criterion has an automated test" is review-only: ACs are free prose and nothing links them to test results. Give every AC a stable ID, require tests to carry it, and add a `verify` stage that reads JUnit XML (emitted by pytest, Jest/Vitest reporters, Go via `go-junit-report`, cargo-nextest, Surefire, RSpec and most others) and fails when an AC on a `completed` task has no passing test.

### Canonical AC ID
- **Mapping:** a task with frontmatter `id: T-042` has AC prefix `AC-T042`; `id: T-009.3` → `AC-T009.3`. The prefix is the task ID with its first hyphen removed, digits copied verbatim — no zero-padding normalisation (`AC-T9-01` and `AC-T009-01` are different IDs, and only the one matching the file's `id` is valid there).
- **Form:** `<prefix>-NN` with two or more digits, e.g. `AC-T042-03`.
- **Matching:** extended regex `AC-T[0-9]+(\.[0-9]+)?-[0-9]{2,}`, accepted only when not preceded by `[A-Za-z0-9.-]` and not followed by `[0-9]` — so `AC-T009-01` never matches inside `AC-T009-010`.
- **Alias for languages that forbid `-`/`.` in identifiers** (Python, Go, Java): replace every `-` and `.` with `_` — `AC-T042-03` ↔ `AC_T042_03`, `AC-T009.3-01` ↔ `AC_T009_3_01`. The group count makes it unambiguous (two numeric groups after `T` = task, three = subtask). A JUnit `<property name="ac" value="AC-…"/>` on the test case is also accepted.
- **Defined vs referenced:** an AC is *defined* only by the bolded ID that opens a `- [ ]` item (or the `~~**ID**~~` superseded form). Any other ID on a line is a *reference*, which must resolve to a defined AC.
- **Never reused or renumbered.** A withdrawn AC is written `- [ ] ~~**AC-T042-03**~~ — superseded YYYY-MM-DD: <reason>`; its ID stays reserved.

## Acceptance criteria
- [ ] **AC-T009.3-01** — Given `tasks/_TEMPLATE.md`, when this task lands, then its AC section uses `- [ ] **AC-TNNN-01** — Given … when … then …`, and `tasks/README.md` documents the mapping, form, matching, alias, defined-vs-referenced, supersede syntax and never-reuse rules above; `ADOPTING.md` gives one test-naming recipe each for pytest (parametrize `ids` or the alias), Jest/Vitest, Go `t.Run`, and JUnit/Surefire `@DisplayName` (verified by cases in `test-doc-assertions.sh`).
- [ ] **AC-T009.3-02** — Given task files, when `scripts/trace.sh` collects ACs, then it reads only `tasks/T-*.md` (never `_TEMPLATE.md`), only lines within the `## Acceptance criteria` section, and keys each *defined* AC to the file's frontmatter `state`. It fails with `AC_PREFIX_MISMATCH` if a defined ID's prefix does not equal the canonical prefix for the file's `id`, with `AC_DUPLICATE` if an ID is defined more than once across all task files, and with `AC_REF_UNKNOWN` if a referenced ID resolves to no defined AC. (So T-009.1's references to other subtasks' IDs are valid.)
- [ ] **AC-T009.3-03** — Given JUnit XML under `$VERIFY_REPORT_DIR`, when `trace.sh` parses it, then a test case *covers* an AC if the ID or its alias matches (per the matching rule) in its `name` or `classname`, or it carries `<property name="ac">` with that ID. Fixture reports parse correctly — under gawk, mawk, BWK awk and busybox awk — for: pytest, jest-junit and go-junit-report output; self-closing `<testcase/>`; single- and double-quoted attributes in any order; tags spanning multiple lines; entity-encoded names (`&amp;`, `&quot;`, `&apos;`, `&lt;`, and numeric `&#NN;` / `&#xHH;`); CDATA; `<system-out>` text containing the string `<failure`; CRLF line endings; and a UTF-8 BOM. A missing awk variant in the pinned image is a FAIL of this suite, not a skip. Unparseable XML, or a `<testsuite>` with `errors>0` (or `failures>0`) and no `<testcase>` children, fails the stage with `JUNIT_MALFORMED <file>` — a suite that crashed mid-run can never read as passing.
- [ ] **AC-T009.3-04** — Given covering test cases for an AC, then the AC is *covered* only if at least one covering case passed (no `<failure>`, `<error>` or `<skipped>` child) **and** no covering case failed or errored. Skipped cases count as neither. A retry is a `<rerunFailure>` / `<flakyFailure>` / `<rerunError>` / `<flakyError>` child, or the same (`classname`, `name`) pair appearing more than once; any failed attempt makes the AC not covered (a flake is a failure).
- [ ] **AC-T009.3-05** — Given a task with `state: completed`, when any of its non-superseded ACs is not covered, then the stage fails and names each AC with its reason code: `AC_NO_TEST`, `AC_FAILING`, or `AC_SKIPPED_ONLY`, each with a `Fix:` line. If `$VERIFY_REPORT_DIR` contains no JUnit files at all, it instead fails once with `NO_JUNIT_REPORTS` and `Fix:` pointing at the JUnit wiring section of `ADOPTING.md` — so an unwired test runner is not misreported as dozens of missing tests.
- [ ] **AC-T009.3-06** — Given a task in `in-progress` or `in-review`, then its uncovered ACs are reported as warnings; given `proposed` or `blocked`, they are listed but not warned; neither fails the stage.
- [ ] **AC-T009.3-07** — Given a test case citing an AC ID that no task defines, that is superseded, or that belongs to a `cancelled` task, then the stage fails and names the test and the reason code (`TEST_REF_UNKNOWN`, `TEST_REF_SUPERSEDED`, `TEST_REF_CANCELLED`).
- [ ] **AC-T009.3-08** — Given a task file with no AC IDs (legacy format), then the stage lists it under `untraced (legacy)` and does not fail, so the starter's existing history does not retroactively break.
- [ ] **AC-T009.3-09** — Given any run, when the stage finishes, then it writes `trace-matrix.md` (task ID, AC ID, task state, covering tests, result; sorted by task ID then AC ID under `LC_ALL=C`; covering tests in one cell joined by `<br>`, capped at 5 with `+N more`; `|` escaped as `\|`, newlines as `<br>`; a fixture test name containing `|` and a newline renders as one row) to `$VERIFY_REPORT_DIR`, contributes a `summary.d/trace.md` section (counts of covered / uncovered / legacy-untraced ACs), and both CI definitions publish it as a build artifact.
- [ ] **AC-T009.3-10** — Given no task with AC IDs and no JUnit files, then the stage reports `N/A (no traced ACs)` and exits 78.
- [ ] **AC-T009.3-11** — Given test names echoed in the stage's output, then they pass through `scripts/lib/sanitize.sh`; a fixture case named with `##vso[` is printed inert.
- [ ] **AC-T009.3-12** — Given the starter's own suites (`scripts/test/*.sh`), then every case is named with the AC ID it verifies, so T-009's subtasks pass this gate when marked `completed` (dogfooding); a fixture marks a T-009 subtask `completed` with one case removed and asserts the stage fails.
- [ ] **AC-T009.3-13** — Docs updated (verified by cases this task adds to `test-doc-assertions.sh`, including `assert_suite scripts/test/test-trace.sh`; pointer-level edits within the `AGENTS.md` growth cap): `AGENTS.md` § 7 and § 8, `.claude/agents/sdet.md` and `.claude/agents/analyst.md` require AC IDs on new tasks and relabel "every AC has an automated test" *mechanically enforced*.
- [ ] **AC-T009.3-14** — `scripts/test/test-trace.sh` covers AC-T009.3-02 … 12 with deterministic fixtures (including a `Fix:` line assertion for every FAIL), names every case with its AC ID, emits JUnit, and is shellcheck-clean.

## Out of scope
- Judging test *quality* (mutation testing, red-before-green) — Tier 2.
- Result formats other than JUnit (TAP, TRX) beyond documenting a conversion step.
- Gating tests that map to no AC (allowed — not every test is a requirement).

## Risks / dependencies
- Depends on T-009.1 (stage interface, report-dir reset, JUnit and sanitiser helpers). Independent of T-009.2 / .4 / .5.
- **Retroactive check:** marking T-009.1 and T-009.2 `completed` happens before this gate exists, so the T-009.3 build PR must pass trace over every T-009.x already `completed` — that is their only retroactive verification.
- JUnit parsing uses `awk` to stay within the tooling floor; the AC-T009.3-03 fixture matrix is what keeps it honest. Trigger: if any awk variant needs a variant-specific workaround to pass the fixture matrix, stop and write the pinned-XML-tool ADR instead of growing the awk code.
