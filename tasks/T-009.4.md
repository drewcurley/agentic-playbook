# T-009.4 — Structured review evidence bound to the diff

## Description
Agent sign-off is a Markdown checkbox list written by the session that wrote the code, and the `/docs/*` consensus gate checks only that a string appears in a commit message. Make the review artifact machine-checkable and tie it to exactly what was reviewed:

- `docs/reviews/<branch-dir>/evidence.json` (branch `chore/x` → dir `chore-x`, i.e. `/` → `-`) records, per role, a verdict and findings, plus two deterministic hashes: the **change hash** and the **criteria hash**.
- **Required roles** are computed from changed paths using `review-scope.conf` (adopter-maintained `<glob> <class>` lines) plus a fixed, built-in **gate** class that adopters cannot remap. The computed set is a floor.
- A `verify` stage fails if evidence is missing, malformed, missing a required role, contains a `BLOCK`, or has stale hashes.

This makes evidence **structured and diff-bound**, labelled *mechanically checked (author-attested)*. Independence is T-009.5.

### Hash definitions
The evidence is committed in the PR it describes, and the ledger is updated after review, so the hashes exclude exactly what legitimately changes after review — and nothing else.
- **Change hash** = sha256 (lowercase hex, via `sha256sum` or `shasum -a 256`) over the concatenation, in this order, of:
  1. `git -c core.quotepath=off diff --raw -z --no-renames --full-index --no-abbrev -O/dev/null --ignore-submodules=none --no-relative BASE...HEAD -- . ':(exclude,glob)tasks/*.md' ':(exclude)docs/reviews/<branch-dir>/'` — modes, full blob IDs and paths only. Blob IDs are content-addressed, so the hash is independent of diff algorithm, context, prefixes, textconv, external diff drivers and git version, and still changes if any byte of any included file changes.
  2. for each `tasks/*.md` changed in the range (sorted, `LC_ALL=C`): its path, then its `HEAD` content with LF line endings, the frontmatter keys `state`, `pr`, `commit`, `branch`, `updated`, `review_artifact` removed, the `## Activity log` section removed, and checkbox state normalised (`- [x]` → `- [ ]`); a deleted task file contributes its path and the marker `DELETED`.
- **Criteria hash** = sha256 over the `## Acceptance criteria` and `## Out of scope` sections of every task in `task_ids`, normalised: LF endings; checkbox state stripped; an *item* is a column-0 `- ` line plus every following line up to the next column-0 `- ` line or the section end, joined with single spaces after trimming each line; any text before the first item in a section is hashed as its own item; items sorted under `LC_ALL=C`; terminated by a newline.
- In CI, `HEAD` is the PR source commit (`System.PullRequest.SourceCommitId`); `BASE` is the merge-base with the target branch.
- Any non-`.md` file under `tasks/`, or any file under `docs/reviews/` outside this branch's dir, fails the stage — nothing can hide under the exclusions.

## Acceptance criteria
- [ ] **AC-T009.4-01** — Given `scripts/review-evidence.schema.json` (a JSON Schema) defining `schema_version` (= 1), `branch`, `task_ids`, `reviewed_head` (the commit reviewed), `change_hash`, `criteria_hash`, `roles` keyed by the fixed role IDs `analyst architect data-engineer backend-engineer frontend-engineer ux-designer sdet devops review-coordinator` (each `{verdict: PASS|PASS_WITH_ITEMS|BLOCK, findings: [string], reviewed_by: string}`), and optional `lenses` keyed `ceo purchasing pm adopter builder investor marketing` (each `{verdict, findings, attested_by?: author|ci}`), when the stage validates evidence, then a `jq` program enforces every rule in that schema, and a fixture per rule proves a violation fails closed (malformed JSON, unknown role, unknown verdict, wrong `schema_version` included; a fixture with `attested_by: author` on a lens passes). Each failure names the JSON path and the rule, e.g. `EVIDENCE_INVALID roles.architect.verdict: "Pass" not in PASS|PASS_WITH_ITEMS|BLOCK`.
- [ ] **AC-T009.4-02** — Given `scripts/review-hash.sh`, when it runs, then it prints the change hash and criteria hash exactly as defined above; a fixture computes the same hashes under a deliberately hostile `~/.gitconfig` (`diff.renames`, `diff.algorithm=patience`, `diff.noprefix`, `diff.relative`, `diff.orderFile`, `diff.ignoreSubmodules=all`, `diff.indentHeuristic`, `core.autocrlf=true`, a textconv driver and an external diff) as under an empty one.
- [ ] **AC-T009.4-03** — Given evidence whose `change_hash` or `criteria_hash` differs from the recomputed value, then the stage fails with `EVIDENCE_STALE` naming which hash, prints `git diff --stat <reviewed_head>..HEAD` (and, for criteria, the changed AC / Out-of-scope items), and gives `Fix: re-review the listed changes and regenerate evidence` — it never suggests pasting new hash values; given only edits to excluded ledger fields, the activity log, or checkbox state after review, then it passes; given an edit to a task's ACs or Out-of-scope list after review, then it fails (criteria stale).
- [ ] **AC-T009.4-04** — Given `task_ids` in evidence, then it must equal the union of Task IDs referenced by commit messages in the range and IDs of task files changed in the range; any mismatch fails.
- [ ] **AC-T009.4-05** — Given `review-scope.conf` and the class → roles table (matching `AGENTS.md` § 5), when `scripts/review-scope.sh` runs, then it prints the union of required roles over all changed paths; a path matching no glob falls into class `feature` (full cycle). In CI, `review-scope.conf` is read from `BASE` (bootstrap rule per T-009.1). Globs match repo-root-relative paths, `*` does not cross `/`, `**` matches zero or more directories. The shipped default maps `contracts/**` → `contract`, `**/migrations/**` and `**/*.sql` → `schema` (so the Data Engineer is required; a fixture proves nested `db/schema/x.sql` matches), and authored `docs/**` → `docs`.
- [ ] **AC-T009.4-06** — Given any changed path matching the built-in gate class — `review-scope.conf`, `tool-versions.lock`, `.devcontainer/**`, `scripts/**`, `.githooks/**`, `azure-pipelines.yml`, `.github/workflows*/**`, `.github/CODEOWNERS`, `contracts/contracts.conf`, `.claude/**`, `.placeholder-allow` — then `architect`, `devops` and `review-coordinator` are required regardless of `review-scope.conf`; and `.github/CODEOWNERS` routes those paths to the gate owners.
- [ ] **AC-T009.4-07** — Given a PR whose changed paths are all in class `lightweight`, then only `review-coordinator` is required; one non-lightweight path raises it to the union.
- [ ] **AC-T009.4-08** — Given evidence where a required role is absent, then the stage fails naming the missing roles; given any role (required or extra) with verdict `BLOCK`, then the stage fails.
- [ ] **AC-T009.4-09** — Given a PR touching authored `/docs/*` (excluding `docs/repos/**`, this branch's `docs/reviews/<branch-dir>/`, and a `docs/contracts.md` change that qualifies for the T-009.2 generated-block carve-out), then all 9 roles are required, each `PASS` or `PASS_WITH_ITEMS`. This becomes the enforced consensus gate. The `unanimous-consensus:` commit string is still accepted alongside evidence, with a deprecation warning, until 2027-01-31 (the current date is read from `VERIFY_TODAY` when set, so fixtures cover both sides of the cutoff without the wall clock); a follow-up task to remove it is opened when this lands.
- [ ] **AC-T009.4-10** — Given any task in `task_ids` with frontmatter `major: true`, then all 7 lens keys must be present in `lenses`, each `PASS` or `PASS_WITH_ITEMS`; `tasks/_TEMPLATE.md` gains `major: false` and `tasks/README.md` documents the field (T-009 already sets `major: true`, so its own build exercises this check).
- [ ] **AC-T009.4-11** — Given an empty diff, then the stage reports `N/A (empty diff)`. Given a non-empty diff and no evidence file, then it fails with `EVIDENCE_MISSING`, printing the expected path, the computed required roles (and lenses if `major: true`), the current hashes and a JSON skeleton to fill in — there is no evidence-free path, including for lightweight changes (a coordinator-only evidence file is required). A fixture reproduces a fork's first real PR (placeholder fill touching `.github/CODEOWNERS`, gate-class) and asserts `EVIDENCE_MISSING` is its only FAIL. Given `VERIFY_PHASE=pre-review` locally, then it reports `SKIPPED (pre-review)` so an agent can run `verify.sh` green before review; given `VERIFY_PHASE=pre-review` in CI mode (T-009.1 definition), then it fails. In non-PR builds it reports `N/A (post-merge)` (T-009.1 AC-09).
- [ ] **AC-T009.4-12** — Given reviewer findings echoed by the stage, then they pass through `scripts/lib/sanitize.sh`. The stage contributes `summary.d/review.md` to the approver summary (T-009.1 AC-06): first line `Review: <PASS|FAIL> — author-attested` (or `independent` when T-009.5 evidence is used), then required roles with verdicts, lens verdicts if required, and stale/missing items.
- [ ] **AC-T009.4-13** — Docs updated (verified by cases this task adds to `test-doc-assertions.sh`, including `assert_suite scripts/test/test-review-evidence.sh`; pointer-level edits within the `AGENTS.md` growth cap): `.claude/agents/review-coordinator.md` and `AGENTS.md` § 7 and § 9 produce `evidence.json` alongside `final.md`; § 5 and § 12 Knob 2 state that lightweight is path-based (a typo in a non-lightweight path gets that path's review); § 8 labels sign-offs *mechanically checked (author-attested)* until T-009.5 is enabled; the consensus rule's restatements (Quick Summary item 6, § 0 Step 4, § 6.6, `docs/README.md`) reference evidence instead of the commit string.
- [ ] **AC-T009.4-14** — `scripts/test/test-review-evidence.sh` covers AC-T009.4-01 … 12 with fixture repos (including a `Fix:` line assertion for every FAIL), names every case with its AC ID, emits JUnit, and is shellcheck-clean.

## Out of scope
- Producing evidence independently of the author (T-009.5).
- Cryptographically signing evidence (Tier 3 provenance).
- Human approvals — still enforced by branch protection + `CODEOWNERS`, unchanged.

## Risks / dependencies
- Depends on T-009.1, and on T-009.2 for the generated-block carve-out (AC-T009.4-09). T-009.5 depends on this evidence format (`schema_version` lets it evolve).
- An adopter's too-loose `review-scope.conf` under-requires roles. Mitigated by the unmatched-path → `feature` default, the non-remappable gate class, and `review-scope.conf` itself being gate-class.
- The lightweight path narrows versus today's § 5 wording (accepted trade-off, ADR 0003).
- Adopter friction: every PR needs evidence. The build review artifact reports time-to-first-green on a fresh fork; if it is too high, the remedy is better tooling (e.g. an evidence-skeleton generator), not new exemptions.
