# T-005 — Optimistic task completion in the work PR

## Description
Separate "mark task done" PRs created noise. Root cause: the terminal step hand-recorded the merge SHA, which is unknowable until after merge. Fix: set `state: completed` in the **work PR itself** (per `AGENTS.md` § 7's original intent), record **`pr:`** (known before merge) instead of chasing the SHA, and rely on the fact that a `completed` line only reaches `main` when the PR merges — so abandon/reopen/revert are self-correcting with no watcher.

This task is dogfooded: it is marked `completed` in its **own PR**, per the very policy it establishes. (Backstory: the prior PR #3 was meant to carry this, but it merged early with only the T-004 ledger sync; this branch re-lands the full policy change cleanly on top of that merge.)
