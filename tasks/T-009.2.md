# T-009.2 — Machine-readable contracts, drift + breaking-change gates

## Description
`contracts.md` is the starter's most important doc and is entirely hand-written. Nothing detects when it falls behind the code, or when a PR breaks a contract. This task moves the source of truth for contracts into machine-readable specs registered in `contracts/contracts.conf`. Each line is `<path> <kind> [<generator command>]`. Paths are relative to the repo root and may live outside `contracts/`, e.g. an app's migrations directory. The task adds three `verify` evidence stages (70–99 range):

1. **Drift:** regenerate each spec from the code with its declared generator, and fail if it differs from the committed spec.
2. **Breaking change:** diff each spec against `BASE`. Fail on a breaking change unless it is declared in an accepted ADR bound to the exact break report.
3. **Index:** the inventory block of `docs/contracts.md` is generated from the specs and must be current.

Every operation and every env/flag entry in a spec carries `x-invariant` and `x-blast-radius`. This enforces T-001.17's invariant-and-blast-radius rule at the source. Cross-cutting invariants that span entries stay hand-authored in `contracts.md`, outside the generated block, under the `/docs` consensus gate. Mechanics are documented in `contracts/README.md`.

**Co-owners:** Data Engineer (migrations / directory-kind adapter interface), Architect (env/flag schema and secret classification).

## Acceptance criteria
- [ ] **AC-T009.2-01** — Given a spec with a generator, then the generator contract is `<cmd> <out-path>`: cwd is the repo root, exit 0 means success, and it runs under `env -i` with `PATH`, `HOME=<tmp>`, `LC_ALL=C` and `TZ=UTC`, plus only the non-secret variable names listed in `CONTRACTS_GENERATOR_ENV`, bounded per run by `CONTRACTS_GENERATOR_TIMEOUT` (default 300 s; a timeout is a FAIL).
  - The drift stage runs it twice into temp dirs. It fails with `GENERATOR_NONDETERMINISTIC` if the two runs differ, and with `SPEC_DRIFT` if the output differs from the committed spec after normalisation: CRLF → LF, JSON canonicalised with `jq -S`, YAML byte-exact.
  - A directory-kind spec is compared recursively by relative path and content.
  - Each failure names the spec and gives `Fix: run <generator> <path> and commit the result`.
- [ ] **AC-T009.2-02** — Given a spec with no generator declared, then the drift stage reports `hand-maintained (no drift check): <path>`. It is visible, not silently passed.
- [ ] **AC-T009.2-03** — Given an `openapi` spec changed on the branch, when the breaking stage runs:
  - Core materialises the spec's whole directory at `BASE` and at `HEAD`, so relative `$ref`s resolve.
  - It runs the pinned `oasdiff breaking` with colour disabled and JSON output, failing at the level set in `contracts.conf` (`oasdiff-fail-on`, default `WARN`, strict, so removing an optional response property also fails).
  - Fixtures name the oasdiff rule ID and level for at least these failing cases: removed path or operation, newly required request property, removed response property, narrowed enum, changed type. Adding an optional request property passes.
- [ ] **AC-T009.2-04** — Given an `env-schema` spec, its required shape is a flat JSON Schema: top-level `properties` and `required`, no `$ref`, and only allowlisted keywords. Each property declares `type`, `x-kind: env|flag`, `x-secret: true|false`, `x-invariant` and `x-blast-radius`, plus `x-gates` for flags. When the breaking stage runs, it fails on any of:
  - a removed property;
  - optional → required;
  - a new required property without `default`;
  - a changed `default` (compared as canonical JSON);
  - a changed `type`;
  - any change to `pattern`;
  - a tightened `enum`, `minimum`/`maximum` or `minLength`/`maxLength`;
  - `x-secret` changing from true to false.

  Adding an optional property passes. A property missing a required `x-` key, a keyword outside the allowlist, or `x-secret: true` together with `default` or `examples` all fail. Each failure names the spec path, the property and the offending key.
- [ ] **AC-T009.2-05** — Given an intended breaking change, it passes for that spec only when the PR adds or contains an ADR in `docs/decisions/` that has `**Status:** accepted`, names the spec path, and records `Contract-Break: <spec-path> sha256:<hex>`.
  - The sha256 is taken over the spec's normalised break report: the oasdiff JSON with `source`/file-path fields stripped, arrays sorted by rule ID, operation and path, then canonicalised with `jq -S` (both sides are materialised at fixed relative paths `base/` and `head/`), or for adapters their stdout with ANSI escapes stripped, CRLF → LF, lines sorted under `LC_ALL=C`, and a trailing newline. A fixture proves the same break gives the same sha on a second run.
  - On success the stage prints the full report, ANSI-stripped.
  - On an undeclared break it fails with `CONTRACT_BREAK_UNDECLARED`, prints the full report, and prints the exact `Contract-Break: <spec-path> sha256:<hex>` line to put in the ADR.
  - A different hash, an ADR that is not `accepted`, or a different spec path still fails.
  - For a directory-kind (migrations) spec, the ADR must also contain `## Deprecation plan` and `## Forward-fix path` headings.
- [ ] **AC-T009.2-06** — Given the registry at `BASE` and at `HEAD`, when the breaking stage runs, then it evaluates the union of both. A spec that is deleted, renamed, removed from `contracts.conf`, or has its `kind` changed is breaking. Its report is the single line `REMOVED <path> <kind>`, `RENAMED <old> <new>` or `KIND_CHANGED <path> <old>-><new>`, and it requires a declaration per AC-T009.2-05.
- [ ] **AC-T009.2-07** — Given the adapter interface `contracts/adapters/<kind> breaking <base-path> <head-path> <spec-path>`: core materialises both sides, and a missing side is passed as the literal `-` (absent). The adapter runs from the BASE gate snapshot (bootstrap rule per T-009.1), in an empty cwd, under `env -i`, bounded by `CONTRACTS_ADAPTER_TIMEOUT`. It writes a deterministic report of at most 1 MiB to stdout, containing no absolute paths, and exits 0 (compatible), 1 (breaking) or any other code (error, which is a FAIL). When an adopter adds a kind (e.g. AsyncAPI, `buf breaking`, `squawk` / `atlas migrate lint`), drift and breaking stages invoke it with no change to core scripts. Two fixture adapters prove the interface: one file-kind, and one directory-kind that inspects files added under a migrations directory. A fixture PR that edits an adapter to `exit 0` is still judged by the BASE adapter.
- [ ] **AC-T009.2-08** — Given specs exist, when `scripts/contracts-index.sh` runs, then it rewrites only the block between `<!-- contracts:generated:start -->` and `<!-- contracts:generated:end -->` in `docs/contracts.md`.
  - **Tables:** one per kind, each with a fixed header:
    - operations: key, method, path, auth scheme, operationId;
    - env vars: key, name, required, default (printed `<secret>` when `x-secret: true`);
    - flags: key, name, default, `x-gates`.
  - **Common columns:** every table also has `x-invariant`, `x-blast-radius`, source spec path, and the spec's blob sha from `git hash-object`, so a local run before commit matches CI.
  - **Row order and keys:** row keys are `<kind>:<id>`, sorted under `LC_ALL=C`.
  - **Cell formatting:** `|` is escaped as `\|`, newlines become `<br>`, there is no trailing whitespace, and the block ends with a single newline.
  - **Failure cases:**
    - The index stage fails with `INDEX_STALE` and `Fix: sh scripts/contracts-index.sh` if the committed block differs from the regenerated one.
    - If specs exist but `docs/contracts.md` or its markers do not, it fails with `INDEX_MISSING` and a pointer to T-001.17.
- [ ] **AC-T009.2-09** — Given a PR that changes `docs/contracts.md`, the consensus requirement is waived only when both of these hold across the whole `BASE...HEAD` range:
  - every byte outside the markers equals `BASE`;
  - the block equals `contracts-index.sh` output.

  Per commit, the commit-msg hook checks only that the commit touches nothing outside the block. If `jq` is unavailable to the hook, the full `unanimous-consensus:` requirement applies. Fixture-tested in both directions.
- [ ] **AC-T009.2-10** — Given no `contracts/contracts.conf`, when the drift, breaking and index stages run, then each reports `N/A (no contracts registered)` and exits 78.
- [ ] **AC-T009.2-11** — Given tool output and spec-derived text echoed by these stages, then it passes through `scripts/lib/sanitize.sh`. A fixture spec with `##vso[` in an `operationId` prints inert.
- [ ] **AC-T009.2-12** — Docs are updated, verified by cases this task adds to `test-doc-assertions.sh`, including `assert_suite scripts/test/test-contracts.sh`. Mechanics live in `contracts/README.md`. In `AGENTS.md` (Quick Summary item 6, § 0 Step 4, § 6.0(3), § 6.6, § 7 step 8, § 8), `docs/README.md` and `tasks/T-001.17.md`, pointer-level edits state that:
  - the inventory is generated from specs;
  - the generated-block carve-out applies wherever the consensus rule is stated;
  - § 8's contract gates are *mechanically enforced* **for declared spec kinds only**;
  - data contracts (tables and consumers), events and jobs without a declared spec remain *review-enforced*.
- [ ] **AC-T009.2-13** — `scripts/test/test-contracts.sh` covers AC-T009.2-01 … 11 with fixture specs (one compatible and one breaking change per rule), including a `Fix:` line assertion for every FAIL. It runs offline against the pinned `oasdiff`, names every case with its AC ID, emits JUnit via `scripts/lib/junit.sh`, and is shellcheck-clean.

## Out of scope
- Shipping production AsyncAPI / protobuf / migrations adapters. Only the documented interface and fixture adapters are in scope; picking a database or IDL is the adopter's call.
- Generating code *from* specs (spec-first codegen): adopter's choice.
- Consumer-driven contract testing (Pact): Tier 2.
- Workspace-model cross-repo breaking-change detection (`integration-map.md` stays review-enforced).

## Risks / dependencies
- Depends on T-009.1 (stages, BASE gate snapshot including `contracts/adapters/`, pinned tool install, JUnit / sanitiser / timeout helpers). Must land before T-009.4.
- Adds `oasdiff` as a pinned dependency, fetched only when an `openapi` spec is registered.
- Generator commands are adopter code from the PR head. They run in the credential-free `verify` job under `env -i` with a timeout. Unlike adapters they are *not* gate code: a generator is part of the system that produces the spec, while the breaking check that judges the spec runs from BASE.
- The strict default (`WARN`) may flag changes adopters consider safe. It is a per-repo setting in `contracts.conf`, and `contracts.conf` is gate-class.
