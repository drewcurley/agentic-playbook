# T-004 — CI provider: Azure DevOps (GitHub Actions parked)

## Description
GitHub Actions is not yet approved for general org use. Teams currently run CI in Azure DevOps with code still in GitHub. This change makes Azure DevOps the active CI for the starter and every fork, parks the GitHub Actions workflow (preserved, inert) for the day Actions is approved, and disables the Actions-based CodeQL default-setup. Config/infra change → Architect + Ops review per `AGENTS.md` § 5.

## Acceptance criteria
- [x] Procedure-check logic extracted to a single shared `scripts/ci-checks.sh` (placeholders, secrets, task-ID, `/docs/*` consensus) so GitHub and Azure DevOps can't drift.
- [x] `azure-pipelines.yml` added (active CI): runs `ci-checks.sh` + shellcheck + the fixture test, plus a PR-body template check via the Azure DevOps REST API.
- [x] GitHub Actions parked: `.github/workflows/checks.yml` moved to `.github/workflows-disabled/checks.yml` (GitHub only runs files under `.github/workflows/`), with a re-enable note. The parked workflow now also calls `ci-checks.sh`.
- [x] CodeQL default-setup disabled (`not-configured`) via API for this repo; documented how to re-enable.
- [x] `.placeholder-allow` updated for the new enforcement files that reference the literal pattern.
- [x] All docs that named `.github/workflows/checks.yml` as "the CI mirror" updated to Azure-DevOps-as-default + Actions-parked (`AGENTS.md` § 7 CI provider, README, `.githooks/README.md`, T-002).
- [x] `shellcheck` clean; `scripts/test/test-setup-workspace.sh` passes; new `scripts/test/test-ci-checks.sh` (7 assertions exercising every gate's pass/fail paths) passes.
- [x] ADO GitHub-hosted gotchas resolved after DevOps review: `pr:` trigger documented as ignored for GitHub repos (branch-policy build validation required); PR-body check rewritten to use the **GitHub** API (opt-in `GITHUB_TOKEN`), not the Azure Repos API; `shellcheck` pinned (no unpinned `apt-get`); diff range computed against the target-branch merge-base (robust to PR merge-ref checkout).
- [x] Default-posture regression (CI-off until pipeline + branch policy wired) called out prominently in `AGENTS.md` § 7 and this task.
- [x] ADR 0002 recorded (`docs/decisions/0002-ci-on-azure-devops.md`).
- [x] Architect + Ops sign-off recorded in the review artifact (both PASS WITH ITEMS; all items resolved).

## Out of scope
- Setting up the Azure DevOps project / GitHub service connection + branch-policy build validation (org infra, not repo content) — documented as the adopter step in `AGENTS.md` § 7.
- Re-enabling Actions: a one-line `git mv` when the org approves it (noted in the parked file + § 7 + ADR 0002).
- End-to-end validation of the pipeline in a live ADO project (no ADO project available here) — the diff/range and PR-body logic are written to the documented ADO behavior; verify on first real wiring.

## Risks / dependencies
- **Per-repo CI:** like the hooks, the Azure DevOps pipeline must be wired into each repo's Azure DevOps project. A repo with no pipeline has no server-side backstop — `--no-verify` then fully bypasses gates.
- The Azure DevOps PR-body check depends on `System.AccessToken` having PR read scope; the pipeline must run with that token available.
- Empty `.github/workflows/` is not tracked by git; the *absence* of any workflow file is what disables Actions and propagates to forks.
