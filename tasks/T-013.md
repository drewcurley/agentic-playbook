# T-013 — Fail closed when git diff/log errors in the hooks and ci-checks.sh

## Description
Follow-up 1 from T-012's review. The gates read their input through pipelines like `added=$(git diff "$rng" -U0 | grep '^+' | grep -v '^+++' || true)`. A pipeline's status is its last command's, and `|| true` swallows that too, so when `git diff` itself fails (unresolvable SHA, no merge base, a shallow clone missing the base, a corrupt object) the gate sees an empty diff and passes. In `scripts/ci-checks.sh` the same happens to `git log "$base..$head"`, so the task-ID and `/docs` consensus loops iterate over nothing. Reproduced: `sh scripts/ci-checks.sh deadbeef HEAD` prints "all procedure gates passed" and exits 0.

Same root-cause class as T-012 ("a tool error read as a clean result"); T-012 closed it for grep, this closes it for git.

## Plan
**`scripts/ci-checks.sh`**
1. Add `die()` (prints `CI-CHECK FAIL: …`, exit 1) for errors after which nothing downstream can be trusted.
2. Before any check: `git rev-parse --verify --quiet "<ref>^{commit}"` for base and head, then `git merge-base "$base" "$head"`; on failure `die "… Failing closed: nothing was checked."` with a hint (shallow clone → fetch depth 0 / fetch the target branch).
3. Capture each git call on its own, then filter: `diff=$(git diff "$rng" -U0) || die "git diff $rng failed. Failing closed."`, then `added=$(printf '%s\n' "$diff" | grep … || true)`. Same for the `--name-only` file list, the per-file diff, `git log` commit list (computed once, reused by checks 3 and 4), per-commit `git log -1 --format=%B`, the docs `--name-only` list, and per-commit `git show --name-only`.

**`.githooks/pre-commit`** — `set -e` already makes the bare `staged_files=$(git diff …)` assignment exit on error, but the piped `added_lines` and per-file `added` don't. Capture the `git diff --cached -U0` output first with `|| fail "git diff failed …"`, then filter.

**`.githooks/commit-msg`** — same treatment for the `docs_touched` diff.

**Tests** — a `git` stub on `PATH` that execs the real git except for one targeted subcommand, which prints an error and exits 128. Fixture cases per acceptance criterion; secret literals assembled at runtime as in T-012.

## Risks / dependencies
- Enforcement-file change: a mistake could block every commit or every CI run. Mitigated by the "clean change passes with empty stderr" controls in each suite and the gate diff.
- CI checkouts must have the base reachable. Both pipelines already use `fetchDepth: 0` / `fetch-depth: 0`, so legitimate runs are unaffected; a shallow-clone misconfiguration now fails loudly instead of passing silently, which is the point.
