# T-012 — Fix pre-commit private-key scan silently skipped

## Description
`.githooks/pre-commit`'s `scan()` helper ran `grep -qE "$pattern"` / `grep -nE "$pattern"`. The private-key pattern `-----BEGIN [A-Z ]*PRIVATE KEY-----` starts with `-`, so grep parsed it as an option, errored (`unrecognized option`, exit 2), and the `if` treated that error as "no match". Result: the local private-key secret scan never ran — the hook exited 0 with a private key staged. Reproduced on macOS (BSD grep 2.6.0, rc=2); GNU grep parses a leading-dash argument the same way (getopt), so Linux is expected to be affected too (the PR's ubuntu CI run is the GNU proof). Found while committing the T-009 plan (PR #2), where the hook printed the grep error and still passed.

The CI mirror (`scripts/ci-checks.sh`) uses one combined alternation pattern that starts with `AKIA`, so CI's private-key check was not affected — now proven by a test.

## Notes
- **Fail-closed rule (Architect, plan review):** the root-cause class is "grep error read as no-match", not the leading dash. Every secret-scan grep now distinguishes exit 0 (match → block), 1 (no match → pass), >=2 (scanner error → block). Applied here rather than as a follow-up because it is ~10 lines and closes the class.
- **grep audit:** `.githooks/commit-msg` (`\bT-…`, `^docs/`, `^docs/repos/`, `unanimous-consensus:…`), `.githooks/pre-commit` (`^+`, `^+++`, `\[insert …`, `^docs/`, `^tasks/INDEX\.md$`, scan patterns), `scripts/ci-checks.sh` (same + combined secret alternation starting `AKIA`), `scripts/aggregate-docs.sh` and `scripts/setup-workspace.sh` (`^\| *…`, `^\[insert`). Only the private-key scan pattern starts with `-`.
- **Gate diff vs `origin/main`:** `pre-commit` — same protected-branch check, same placeholder check, same 6 `scan` calls and labels, same block messages; added one fail-closed exit. `ci-checks.sh` — same pattern, same block message; added `--` and one fail-closed error. `commit-msg`, `pre-push` unchanged.
