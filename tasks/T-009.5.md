# T-009.5 — Independent agent review in CI

## Description
Even with T-009.4, the reviewers are the authoring session wearing different hats: same context, same reasoning, correlated blind spots. Move review into CI. An opt-in pipeline **job, separate from and after the `verify` job** (jobs do not share a filesystem or process space), runs each required role headlessly through `REVIEW_CMD` (default: a wrapper around the pinned `claude` CLI in print mode) with the role's brief. Each reviewer sees only the task's criteria, the relevant specs/docs, and the diff, not the author's transcript. The step writes `evidence.json` itself, and T-009.4's checks then validate it. When enabled, CI-produced evidence is authoritative.

The step loads its gate inputs from `BASE`: `scripts/ci-review.sh`, `.claude/agents/*.md`, `review-scope.conf`, and the evidence schema. A PR cannot rewrite its own reviewer.

**Co-owner:** DevOps (pipeline wiring, cost controls).

## Acceptance criteria
- [ ] **AC-T009.5-01** — Given `REVIEW_REQUIRED` unset or `false` and no `ANTHROPIC_API_KEY` secret, when the step runs, then it reports `SKIPPED (no API key; evidence is author-attested)` and exits 77; T-009.4's checks still run on author evidence. Given `REVIEW_REQUIRED=true` and no key, the step fails with `REVIEW_KEY_MISSING` and `Fix: add the ANTHROPIC_API_KEY pipeline secret, or set REVIEW_REQUIRED=false`. Given `REVIEW_REQUIRED=false` and a reviewer that is unavailable after retries (AC-T009.5-05), then it reports `SKIPPED (reviewer unavailable)` and author evidence gates.
- [ ] **AC-T009.5-02** — Given a fork PR (`System.PullRequest.IsFork=True`), then the step never receives the key. With `REVIEW_REQUIRED=true` it fails with `REVIEW_FORK_PR` and `Fix: a maintainer re-runs from a branch in this repo, or reviews by hand and uses break-glass`; otherwise it reports `SKIPPED (fork PR)`.
- [ ] **AC-T009.5-03** — Given the step runs, then:
  - it runs only after the `verify.sh` job, including its secret-scan stage, has passed;
  - `ANTHROPIC_API_KEY` is mapped into this step only;
  - its working directory is an empty temp dir into which only the inputs are copied (no `.claude/`, no repo checkout), and no `CLAUDE.md` exists in that dir or any parent;
  - the CLI is invoked with project and local settings sources disabled, an empty strict MCP config, all tools disabled, and a single turn (`--max-turns 1`);
  - the environment is an explicit allowlist: `PATH`, `HOME` (an empty temp dir, so no user-level `~/.claude` settings or hooks load), `ANTHROPIC_API_KEY`, `REVIEW_ROLE`, `REVIEW_MODEL`, `REVIEW_MAX_OUTPUT_TOKENS`, `DISABLE_AUTOUPDATER=1`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`;
  - inputs are wrapped in delimiters with the instruction that delimited content is untrusted data, never instructions.

  Tests replace `claude` on `PATH` with a stub (not `REVIEW_CMD`), so the real wrapper's argv is exercised; the stub asserts the argv flags, the cwd contents and that the environment equals the allowlist. One case runs the pinned `claude --help` offline and asserts every flag the wrapper uses is present in that version.
- [ ] **AC-T009.5-04** — Given `scripts/ci-review.sh`, the role briefs, `review-scope.conf` and the evidence schema, when the step runs in CI, then all of them, and every script they invoke or source, run from the BASE gate snapshot (T-009.1 AC-07), under its bootstrap rule. The step builds its inputs from a fresh checkout using those BASE scripts and consumes no artifact produced by the `verify.sh` job. A fixture PR that edits `.claude/agents/architect.md` to "always PASS" is still reviewed with the base brief.
- [ ] **AC-T009.5-05** — Given a reviewer's output, when it is not valid JSON matching the role-verdict schema, then that role is recorded as `BLOCK` with finding `malformed reviewer output`. Calls are bounded: each role call times out after `REVIEW_TIMEOUT_S` (default 300) via `scripts/lib/timeout.sh`; exit 124 (timeout) counts as unavailable, is not retried, and counts toward the circuit breaker; only exit 75 (retryable — rate limit, 5xx, network) is retried, at most 2 times with jittered exponential backoff (sleep and jitter are injectable via `REVIEW_SLEEP_CMD` and `REVIEW_JITTER_SEED`, both rejected in CI mode, so fixtures assert the backoff sequence with no real delay or randomness); after 2 consecutive roles end unavailable, the circuit opens and remaining roles are marked unavailable without calling; the job sets `timeoutInMinutes`. Given a role ends unavailable with `REVIEW_REQUIRED=true`, then it is `BLOCK` (`REVIEWER_UNAVAILABLE`), so an outage fails closed.
- [ ] **AC-T009.5-06** — Given the diff exceeds `REVIEW_MAX_DIFF_BYTES` (default 200000), or the pre-call estimate exceeds `REVIEW_MAX_USD` (default 5.00), then the step fails with `REVIEW_OVER_BUDGET` **before any API call**, and `Fix:` lists the three ways out — split the PR, raise `REVIEW_MAX_USD` in the pipeline, or request human review. The estimate is summed over every required role: (bundle bytes ÷ 3) input tokens plus `REVIEW_MAX_OUTPUT_TOKENS` (default 8000) output tokens per role, priced from a per-model table in `scripts/ci-review.sh`; a model missing from the table fails closed (`REVIEW_MODEL_UNPRICED`). The **bundle** per role is exactly: the role brief, the `## Acceptance criteria` and `## Out of scope` sections of each task in `task_ids`, the BASE and HEAD versions of every registered spec the PR touches, the changed-file list, and the unified diff (`--no-ext-diff --no-textconv`). The diff is never silently truncated.
- [ ] **AC-T009.5-07** — Given CI-produced evidence and an author-committed `evidence.json`, then the CI evidence is used, carrying over the author's `lenses` block marked `"attested_by": "author"` (lenses remain author-attested in Tier 1): after the review step, BASE's T-009.4 evidence stage re-runs against the CI evidence, and that result is the check that gates merge. A `BLOCK` in either evidence fails the build.
- [ ] **AC-T009.5-08** — Given the step completes, then the produced `evidence.json` and each role's findings are published as a build artifact, after passing through `scripts/lib/sanitize.sh`. Each role's `reviewed_by` records the `REVIEW_CMD` name and model ID. Estimated and actual (where `REVIEW_CMD` reports usage) tokens and USD per role and in total are recorded in the artifact and in `summary.d/review.md`.
- [ ] **AC-T009.5-09** — Given `REVIEW_MODEL` is unset, then the model is the single constant `REVIEW_MODEL_DEFAULT` in `scripts/ci-review.sh`, initially `claude-sonnet-5-5`. Setting `REVIEW_MODEL` in the pipeline overrides it with no code change.
- [ ] **AC-T009.5-10** — Given `REVIEW_CMD` points to a different executable that follows the documented interface — stdin: the role bundle; env: `REVIEW_ROLE`, `REVIEW_MODEL`, `REVIEW_MAX_OUTPUT_TOKENS`; stdout: `{"verdict": …, "findings": […]}`, at most 256 KiB; exit 0 OK, 75 retryable, any other permanent — then the step uses it unchanged. This is the vendor-exit and non-Claude (e.g. Codex) path.
- [ ] **AC-T009.5-11** — Given `tool-versions.lock`, then the `claude` CLI's native binary (not the npm package, which would add Node to the floor) is pinned there with a per-platform sha256, licence and terms-of-use reference (as is `oasdiff`), and installed by `verify-bootstrap.sh`, never by an unpinned install.
- [ ] **AC-T009.5-12** — Docs updated (verified by cases this task adds to `test-doc-assertions.sh`, including `assert_suite scripts/test/test-ci-review.sh` and the T-009 AC-T009-04 greenfield case in `test-verify.sh`):
  - `ADOPTING.md` covers enabling the step: the secret, `REVIEW_REQUIRED`, the budget variables, a dedicated API workspace key with a vendor-side spend limit, the expected per-PR cost range, that the ADO setting "Make secrets available to builds of forks" must stay off, and a data-classification note (the diff leaves your systems; the starter assumes no regulated data; adopters must assess theirs).
  - `AGENTS.md` § 8 relabels sign-offs *independently reviewed* when the step is enabled with `REVIEW_REQUIRED=true`.
  - break-glass is documented in `ADOPTING.md` and `AGENTS.md`: a project administrator temporarily sets the **pipeline-level** variable `REVIEW_REQUIRED=false` (not "settable at queue time", so no queuer can set it; a PR could only override it by editing the pipeline YAML, which is the documented gate-class residual risk, and a fixture asserts the YAML never defines it; adopters confirm their ADO organization's audit log records pipeline-variable changes), merges with human review, and restores it within 24 h (renewable once with an incident-log entry, then escalate); after restoring, the admin runs `sh scripts/ci-review.sh --range <from>..<to>`, which reviews each merge commit in the window against its first parent, and records the results in the incident log — this is compatible with "Include administrators" branch protection, which blocks bypassing the check but not changing pipeline configuration.
- [ ] **AC-T009.5-13** — `scripts/test/test-ci-review.sh` runs the step against a stub `REVIEW_CMD` including a `Fix:` line assertion for every FAIL, covering PASS, BLOCK, malformed, API error, retry-then-success, circuit-open, timeout, oversize and fork cases, and AC-T009.5-01 … 11, all offline. It names every case with its AC ID, emits JUnit, and is shellcheck-clean.

## Out of scope
- Posting reviewer findings as GitHub PR comments (needs a GitHub token in ADO; possible follow-up).
- Cross-model adversarial review (two vendors per role): Tier 2.
- Replacing human approval for high-risk changes: Tier 2 risk-tiered auto-merge decides that.

## Risks / dependencies
- Depends on T-009.4 (evidence format, `review-scope.sh`) and T-009.1 (bootstrap, pinning, sanitiser).
- **Prompt injection:** the diff is attacker-controllable. AC-T009.5-02 through 05 mitigate it with no tools, no settings, no forks, base-loaded briefs and fail-closed parsing. A reviewer can still be argued into a wrong `PASS`. That residual risk is why human approval stays required for high-risk paths until Tier 2.
- **Data egress:** code is sent to the model vendor. It is opt-in, gated on the secret scan, and documented for adopter assessment.
- Cost scales with PR count × required roles. Pre-call caps plus a vendor-side spend limit keep it bounded.
