# T-028 — Stop the commit-msg hook echoing git's warnings, and pin its diff

## Description
`.githooks/commit-msg` runs `git -c core.quotePath=false diff --cached --no-renames --name-only --diff-filter=ACMR` to find staged `/docs` changes.

- **It leaks.** On 2026-11-14, when the staged changes included a gitlink (a submodule entry), that call printed git's `.gitmodules` warning, quoting a submodule name ("ignoring 'submodule.<name>.path' which may be interpreted as a command-line option"). A submodule name is a quoted config subsection, so it can carry escape bytes into the terminal and into the transcripts of agents that run the hook.
- **It's unpinned.** It lacks starter T-024's protections:
  - no `-c diff.relative=false`, so run by hand from a subdirectory, the `/docs` check sees only that directory;
  - no `cd` to the top of the work tree;
  - `--diff-filter=ACMR`, so deleting a docs file (D) or turning one into a symlink (T) skips the consensus check. CI's check uses no filter, so it still catches both.

  Git already runs hooks from the top of the work tree, so the first two pins only matter when someone runs the hook by hand.

The task is to give its git calls the `2>/dev/null` capture and T-024's pins, and cover the hook in `check_git_quiet`.

## Out of scope
- The checkout step (starter T-025) and `ci-pr-checks.sh` (starter T-027).

## Risks / dependencies
- The hook only runs locally; CI's `/docs` check in `scripts/ci-checks.sh` is the enforcing copy, so a hook gap is a convenience gap, not a bypass.
