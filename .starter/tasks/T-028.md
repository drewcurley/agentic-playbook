# T-028 — Stop the commit-msg hook echoing git's warnings, and pin its diff

## Description
`.githooks/commit-msg` runs `git -c core.quotePath=false diff --cached --no-renames --name-only --diff-filter=ACMR` to find staged `/docs` changes.

- **It leaks.** On 2026-11-14, when the staged changes included a gitlink (a submodule entry), that call printed git's `.gitmodules` warning, quoting a submodule name ("ignoring 'submodule.<name>.path' which may be interpreted as a command-line option"). A submodule name is a quoted config subsection, so it can carry escape bytes into the terminal and into the transcripts of agents that run the hook.
- **It's unpinned.** It lacks starter T-024's protections:
  - no `-c diff.relative=false`, so run by hand from a subdirectory, the `/docs` check sees only that directory;
  - no `cd` to the top of the work tree;
  - `--diff-filter=ACMR`, so deleting a docs file (D) or turning one into a symlink (T) skips the consensus check. CI's check uses no filter, so it still catches both.

  Git already runs hooks from the top of the work tree, so the first two pins only matter when someone runs the hook by hand.

The task is to give its git calls the `2>/dev/null` capture and T-024's pins, and cover the hook in `check_git_quiet`.

## Acceptance criteria
- [ ] 1. **The hook runs from the top of the work tree.** Like `.githooks/pre-commit`, it runs `top=$(git rev-parse --show-toplevel 2>/dev/null)` and `cd "$top"`, and fails closed if either fails. Both lines come after `msg=$(cat "$msg_file")`, since `$1` can be a relative path.
- [ ] 2. **Its diff is pinned and uses CI's file list.** The call becomes `git -c core.quotePath=false -c diff.relative=false diff --cached --no-color --no-renames --name-only 2>/dev/null`. It has no `--diff-filter`, like CI's `/docs` check. Deleting an authored docs file, or turning one into a symlink, now needs the `unanimous-consensus:` line locally too. CI already requires it.
- [ ] 3. **Git's stderr is discarded.** A failing call still blocks with the existing message.
- [ ] 4. **Tests in `scripts/test/test-commit-msg.sh`:**
  - a staged gitlink with a hostile `.gitmodules` (a canary submodule name with an ESC byte): neither appears in the hook's output, read from both stdout and stderr. The precondition shows the unpinned call prints the warning in that repo; if it doesn't, the case fails rather than skips;
  - deleting a docs file without the consensus line blocks, and with it passes;
  - turning a docs file into a symlink without the line blocks;
  - with `diff.renames=true`, renaming `docs/x.md` to `other/x.md` without the line blocks;
  - run by hand from `sub/` with `diff.relative=true`, a staged docs file blocks;
  - every existing case passes.
- [ ] 5. **Wiring checks cover the hook.**
  - It is in starter T-027's `quiet_scripts` list for `check_git_quiet`.
  - A new check requires, on the hook's diff, `-c core.quotePath=false`, `-c diff.relative=false`, `--no-color` and `--no-renames`, and no `--diff-filter`, plus the `top=` and `cd "$top"` lines. Two of these pins cover the same failure, so no behaviour test can catch either one being dropped on its own.
  - A fixture fails each rule.
- [ ] 6. **Docs.** The `commit-msg` rows in `.githooks/README.md` say a deleted or retyped docs file counts. The `ADOPTING.md` sync note says the hook now blocks these locally, as CI already did.
- [ ] 7. **No regression.** Every suite passes under sh, dash and bash, and shellcheck is clean.

## Out of scope
- The checkout step (starter T-025) and `ci-pr-checks.sh` (starter T-027).
- Git's own output from `git commit`, `git add` and `git status`, which prints the `.gitattributes` warnings around the hook. Nothing in the hook can silence it (compare starter T-025).
