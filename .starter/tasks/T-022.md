# T-022 — GitHub Actions on by default, Azure DevOps supported

## Description
The owner: "GitHub Actions shouldn't be disabled or not recommended at the playbook user level", and fix the loose ends left after T-021:
1. require the CI checks on this repo's `main`;
2. drop the "GitHub Actions not yet approved for general org use" framing;
3. pin the Ubuntu image instead of `ubuntu-latest`;
4. record that push-to-`main` is proven;
5. say how to match CI's shellcheck locally;
6. T-021's Architect follow-ups.

ADR 0002 parked the Actions workflow because one organization hadn't approved Actions. That organization keeps a separate copy of the starter, so the public starter now runs Actions by default and keeps Azure DevOps as a supported alternative. ADR 0005 supersedes ADR 0002.

## Acceptance criteria
- [x] 1. The workflow is active at `.github/workflows/checks.yml`. Tests accept it at either path and fail if both exist (`test-ci-wiring.sh`).
- [x] 2. No user-facing doc, script, seed task, CI comment or deck text calls Actions parked or unapproved (`test-ci-wiring.sh` framing check, `test-deck.sh` text check).
- [x] 3. ADOPTING § 4 "pick one":
  - a one-line rule, with 4a GitHub Actions (default) and 4b Azure DevOps (park Actions unless running both);
  - "land `scripts/` first" and "running isn't enforcing" apply to both;
  - each path has a "Done when" line;
  - 4a covers true forks, orgs that block Actions, Actions settings (including SHA-pinning policy and Dependabot alerts), and minutes from T-019's timings (about 3 billed minutes per push to a PR, about 2 more when the deck builds).

  § 5 has a table of checks per system with their expected source, plus renaming and park guidance. The break-glass note and the shipped checklist are no longer tied to one system, and there's a sync note for existing forks.
- [x] 4. ADR 0005 supersedes ADR 0002, whose status line is the only change to it. It covers the threat model, why CI isn't a security boundary, source-pinned checks, which checks to require, the difference in credentials between the two systems, SHA-pinned actions and cost.
- [x] 5. Both CI files run `ubuntu-24.04`. `test-ci-wiring.sh` fails on an uncommented `ubuntu-latest` or on mismatched images, with fixtures for both.
- [x] 6. The Actions workflow runs with least privilege, with a fixture for each rule in `test-ci-wiring.sh` (which also checks every Azure job sets `timeoutInMinutes`):
  - `permissions: {}` at the top;
  - `contents: read` on each job and no write access;
  - `persist-credentials: false` on every checkout;
  - `actions/checkout` pinned to commit `11d5960a…` (v4.4.0);
  - `timeout-minutes` on each job;
  - no `${{ }}` inside `run:` scripts.
- [x] 7. The Azure procedure step chooses the PR or branch path from env vars, inside `# BEGIN/END pr-mode`. It fails closed on an empty `BUILD_REASON` under Azure, or on a PR build with no target or one that looks like an option, and no `$(Build.*)` or `$(System.*)` macro is left in the file. `test-ci-pr-checks.sh` § 10 covers this against a fixture repo:
  - `main` and `refs/heads/main` targets;
  - a non-PR reason that has a target;
  - a branch build;
  - an empty target, an option-like target and an empty reason;
  - a secret in the PR, to prove the gate really runs.
- [x] 8. The Azure PR-body block uses only env vars (no macros). A PR build with an empty or malformed number or repo fails before the token is used. The token reaches curl as the whole header on stdin (`-H @-`). `test-pr-body-check.sh` checks the arguments contain `-H @-` and no `Bearer`, that stdin is exactly the header, and the fail-closed cases. It passes 71 checks across bash, sh and dash.
- [x] 9. `.githooks/README.md` shows how to run CI's shellcheck locally. `test-ci-wiring.sh` fails if its version or checksum differs from the CI pin.
- [x] 10. `test-setup-hooks.sh` accepts the workflow at either path, with a fixture for each. The anchor in `test-deck.sh` is updated, and the deck is rebuilt and compared with `DECK_BUILD_REQUIRED=1`.
- [x] 11. T-021 gets a dated addendum saying push-to-`main` is proven on Azure. This file and its INDEX row are added.
- [ ] 12. After this PR's runs, this repo's `main` requires the four source-pinned checks. Recorded under "Branch protection" below.
- [x] 13. The deck job builds only on PRs that touch the deck or its CI wiring (owner, after the plan review; addendum H, reviewed by DevOps, SDET and Architect):
  - `scripts/ci-deck-needed.sh` says skip only on a confirmed PR build (event and merge ref, with the PR head as the merge's second parent), and only when no listed file changed. Pushes, manual runs and anything unclear build.
  - Both CI files share an identical `deck-gate` block that runs the target branch's copy. Only an explicit skip verdict writes the marker, which `test-deck.sh` honors. Deck checkouts are two commits deep.
  - `test-ci-deck-needed.sh` (sh and dash) covers the decision on both systems, shallow clones, git and grep failures, the gate's broken or forged verdicts, a PR that rewrites the script, and that each file's gate marker is the one its suite step reads. Mutations of the PR-build checks (event, merge ref on both systems), the head check and the gate's exit rule each fail it. `test-deck.sh` checks the skip leaves a notice in the CI log.
  - `test-deck.sh`'s fixture copies exactly the script's `--list`, so a missing input fails its "unmodified copy passes" check.

## Out of scope
- Enabling CodeQL on this repo (the owner's call).
- Dependabot version-update PRs: their commits carry no Task ID and would fail the procedure gate. Pins are bumped by hand, like the shellcheck pin; Dependabot alerts are recommended instead (ADOPTING § 4a).
- GitLab or other CI systems.

## Risks / dependencies
- This PR is the first live run of the un-parked workflow, the pinned images and the env-var changes on both systems. If Actions doesn't start on the PR (seen once in T-019), close and reopen it.
- Existing forks see Actions start running on sync. The ADOPTING § 1 note tells Azure-only teams to keep it parked.
- Rollback is `git revert` of the merge. For branch protection, remove the four required checks; the protection JSON saved before the change is below.
