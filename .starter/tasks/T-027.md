# T-027 — Make ci-pr-checks.sh discard git's stderr

## Description
Starter T-024 made every git call in `scripts/ci-checks.sh` and `.githooks/pre-commit` discard git's stderr, enforced by `check_git_quiet` in `scripts/test/test-ci-wiring.sh`. `scripts/ci-pr-checks.sh` wasn't covered.

- **Current calls are quiet.** Its git calls today are `rev-parse --verify`, `ls-tree --full-tree` and `cat-file blob`. On 2026-11-14 none of them printed a warning against a hostile `.gitattributes` or `.gitmodules`. So this is defence in depth.
- **Why do it anyway.** A future call there, such as a diff, would put a PR's bytes into the log.

The task is to give every git call in `ci-pr-checks.sh` the same `2>/dev/null` capture, and extend `check_git_quiet` and its fixtures to the script.

## Out of scope
- The checkout step (starter T-025) and the `commit-msg` hook (starter T-028).

## Risks / dependencies
- `ci-pr-checks.sh` runs on the target branch's copy, so the change protects PRs only after it lands on main.
- Its two `git cat-file blob … > file` calls are redirects, not `$( )` captures. `check_git_quiet` flags any git call outside a capture, so either the check or those calls must change.
- T-028 also edits `se_scripts` and `check_git_quiet` in `scripts/test/test-ci-wiring.sh`; don't build the two at the same time.

## Notes
- Related idea (DevOps, T-024 build review): on a git failure, capture its stderr to a temp file and print it through `se_safe`, so a red build keeps git's reason without risking log injection. Applying it to all three scripts would reach into T-024's scripts, so it belongs in a separate task, not this one.
