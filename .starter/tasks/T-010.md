# T-010 — Ledger and docs housekeeping

## Description
Inconsistencies found while assessing the starter (T-009), deliberately kept out of T-009's scope:
- `tasks/README.md` "When you commit" says to record `commit` (short SHA); `AGENTS.md` § 7 step 9 says never hand-record it.
- `tasks/INDEX.md` is described as generated, but no generator script exists.
- `tasks/INDEX.md` PR numbers for T-003 … T-008 refer to a previous repository (this repository's PR #1 is the Sponsors change).
- `AGENTS.md` § 7 step 4 moves a task to `in-progress` on plan approval; `tasks/README.md` defines `in-progress` as "build happening on a branch". There is no state for "plan approved, build not started".
- A home-directory `CLAUDE.md` outside this repo describe 8 agents and different lens names; the repo defines 9 agents and the Adopter/Builder lenses. (Outside this repo — record the mismatch and recommend alignment.)

**Persona:** engineers and agents reading the ledger.

## Acceptance criteria
Rechecked on 2026-11-14 against `main` 3ecb1b6. Item 4 (no "plan approved, build not started" state) is already fixed: starter T-026 made `in-review` cover the wait for the owner's approval (`tasks/README.md` States table). Items 1, 2, 3 and 5 still hold.

- [ ] 1. **One rule for `commit`.** `tasks/README.md` § "When you commit" stops telling you to record `commit` (short SHA). It says to leave `commit` alone, because it is optional and derived after merge, matching `AGENTS.md` § 7 step 9. A phrase check in `scripts/test/test-task-ledgers.sh` fails if `` `commit` (short SHA)`` comes back in `tasks/README.md`.
- [ ] 2. **INDEX.md is described as it is.** No generator exists. Every place that says INDEX is generated, regenerated or a derived view says instead that it is kept by hand, mirrors each task's ID, owner, state and PR, and is checked in CI; a merge conflict there is resolved from the task files. Those places are `AGENTS.md`, `README.md`, `tasks/README.md`, `tasks/INDEX.md`, `tasks/T-001.md`, `.starter/tasks/INDEX.md`, `.claude/agents/review-coordinator.md`, `.githooks/README.md` and `.githooks/pre-commit`, including `AGENTS.md` § 7 steps 9 ("the INDEX regen can backfill it") and 14, and the review-coordinator's two checklist lines. The pre-commit warning becomes, exactly: `<paths>: keep each row's ID, owner, state and PR in step with its task file; CI checks this (scripts/test/test-task-ledgers.sh).` A phrase check fails if `regen` (any case) appears in any of those nine files.
- [ ] 3. **CI checks INDEX against the task files,** in `scripts/test/test-task-ledgers.sh`, for `tasks/INDEX.md` and `.starter/tasks/INDEX.md`. It reuses starter T-023's row parser, which already matches rows to files both ways, and adds:
  - **Owner, state and PR.** Columns are found by header name. Each row's owner, and its State and PR cells where the table has them, match the frontmatter. `#N` and `N` are equal, and the cell `— (earlier repo #N)` matches `pr: —   # earlier repo #N`.
  - **Section fits state, both ways.** A row is under a `## Backlog…` heading if and only if it is `proposed`, under `## Completed` if and only if `completed`, and under `## Cancelled / Superseded` if and only if `cancelled`. `## In flight` holds only `in-review`, `in-progress` or `blocked`. A row under any other heading fails with the heading's name, so a fork that adds a section sees why.
  - **Safe output.** A failure names the row's ID and the field, printed with every byte outside `[A-Za-z0-9._/ -]` as `?`.
  - A fixture breaks each rule.
- [ ] 4. **No PR number points at the wrong repository.** T-003 to T-008 were merged in the template's earlier repository, but their `pr:` fields give numbers that, in this one, are other PRs. Each becomes `pr: —   # earlier repo #N`, and the INDEX PR cell becomes `— (earlier repo #N)`. A check fails unless all six files carry that form.
- [ ] 5. **The one row that drifts today is fixed.** `tasks/INDEX.md` lists T-001.8's owner as `test-engineer`, but its file says `sdet`, the agent's name. The row becomes `sdet`.
- [ ] 6. **The outside mismatch is recorded, not fixed.** A home-directory `CLAUDE.md` outside this repo still describes 8 agents and different lens names. This task's Notes record that, with the recommendation to point it at `AGENTS.md`, and give no path or name. Nothing outside the repo changes.
- [ ] 7. **Forks are told.** The `ADOPTING.md` sync note says the new check can turn a fork's `scripts` job red when its INDEX has drifted, and that the failure names the row to fix.
- [ ] 8. **No regression.** Every suite passes under sh, dash and bash, and shellcheck is clean. The tests that pin the old warning text (`scripts/test/test-pre-commit.sh:270,463` and `scripts/test/test-ci-wiring.sh:495`) are updated to the new text, and the plan-approval anchor sentences that `test-task-ledgers.sh` checks still pass.
