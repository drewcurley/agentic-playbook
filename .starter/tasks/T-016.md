## Risks / dependencies
- CI gains its first Python dependencies, and `pip install` needs the network. A registry outage turns the build red, not falsely green.
- Supply chain: publishers of the five packages gain code execution on hosted build VMs with open egress. The `deck` job keeps no git credentials, maps no secrets and publishes nothing, which limits a compromise but doesn't remove it: Azure's job token still exists on the agent, so `ADOPTING.md` § 4 says to keep the build identity read-only and project-scoped. Hashes stop a replaced release from installing. A fork on a self-hosted pool loses the per-job VM isolation, and `ADOPTING.md` § 4 says so.
- Forks that changed the deck will fail the suite on sync until they update its expected values or delete the deck.
- Rollback: revert the PR. A fork on GitHub Actions that requires the deck check must remove that requirement first, or the revert waits on a check that never reports.
