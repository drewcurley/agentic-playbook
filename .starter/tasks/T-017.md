# T-017 — Stop prompting on feature-branch pushes, keep prompts for protected branches

## Description
`.claude/settings.json` asked before every `git push`, and `ask` rules still prompt under bypass permissions. The flow in `AGENTS.md` says to push right after sign-off, so every feature-branch push interrupted the user. The rule now asks only when a push names a protected branch or uses a force flag. The user made the settings edit themselves.

## Acceptance criteria
- [x] `ask` has one substring rule for each branch in the `protected` list in `.githooks/pre-push`, plus `*--force*` and `* -f*`. The blanket `Bash(git push:*)` is gone.
- [x] The `deny` rules for `git push --force` and `git push -f` are unchanged, and `allow` doesn't pre-approve any push.
- [x] New `scripts/test/test-claude-settings.sh` asserts all of the above, reads the branch names from the hook, and shows each check failing on a fixture. Wired into both CI files.
- [x] The `ADOPTING.md` intro says a bare `git push` while on `main` isn't caught.

## Out of scope
- Branch protection on this repo, and the hook files' committed modes. Architect raised both; they are the user's call.

## Risks / dependencies
- The test pins the rule strings. Matching was checked against the permissions docs and a regex simulation, not Claude Code itself, so the next real feature-branch push is the live check.
- A branch name containing a protected word, like `feat/domain`, prompts too. That fails safe.
- A bare `git push` on `main`, `git push -fu origin feat` and `+feat` don't prompt. The last two reach non-protected branches only.
