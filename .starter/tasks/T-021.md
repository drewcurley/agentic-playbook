# T-021 — Fix what the first real Azure DevOps runs found

## Description
`azure-pipelines.yml` had never run. The owner set up a free Azure DevOps organization and project, and we ran the pipeline against this repo on two throwaway draft PRs: #15 (a harmless change) and #16 (the same plus a commit with no Task ID, made with hooks bypassed). No Azure branch policy was configured. Two pipelines were built from the same file, so each PR got two sets of checks.

What the runs showed:
1. **PRs build with no Build Validation policy.** Azure's checks appeared on both PRs within seconds of opening (Azure builds 5–8, reason `pullRequest`). Our docs said the YAML `pr:` trigger is ignored for GitHub repos and Build Validation is required. That was backwards: Build Validation is the Azure Repos mechanism, and for GitHub the `pr:` trigger plus a required check in GitHub branch protection is the setup.
2. **The procedure gate works on Azure.** On #15 the gate step passed against Azure's synthetic merge head. On #16 it failed with `CI-CHECK FAIL: Commit fdb7e47… is missing a Task ID (T-NNN)`.
3. **The PR-body step failed every PR without a `GITHUB_TOKEN`.** An undefined pipeline variable reaches `env:` as the literal text `$(GITHUB_TOKEN)`, so the "not set" test passed it, curl got a 401, and `curl | jq` hid that failure, so the step reported all six template sections missing.
4. **Azure's pinned shellcheck v0.10.0 flagged SC2015** in `scripts/test/test-setup-hooks.sh`, which local 0.11.0 doesn't. GitHub Actions used the runner's floating preinstalled version, so the two CI systems could disagree.
5. The first pipeline failed for a while with *"No agent found in pool Azure Pipelines which satisfies the specified demands: Agent.Version -gtVersion 2.163.1"* right after the free tier was granted (builds 1–3, including a one-step echo pipeline, so not our file), then ran normally on the PRs.
6. Azure names its checks `<pipeline name>` (overall, fails if any job fails) and `<pipeline name> (<job>)`.

#15 carries the SC2015 fix (6a611d5) and the PR-body fix (fc69228); with both, all eight checks passed on both pipelines. The checksummed shellcheck download, the new suite and the GitHub workflow changes came after that and haven't run on a CI agent: this PR's own Azure run is their first live test, and the GitHub workflow stays untested while it's parked.
