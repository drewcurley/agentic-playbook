# T-025 — Keep the CI checkout step's git warnings out of the log

## Description
Starter T-024 made `scripts/ci-checks.sh` and `.githooks/pre-commit` discard git's own stderr, because git's warnings quote a PR's `.gitattributes` and `.gitmodules`. The CI checkout step runs git before either script: `actions/checkout` in `.github/workflows/checks.yml`, and `checkout: self` in `azure-pipelines.yml`.

- **What leaks.** An invalid attribute name in a PR's `.gitattributes`, such as `##vso[task.logissue`, is printed by `git clone` and `git status` as "`<name>` is not a valid attribute name". T-024's build review confirmed this on 2026-11-14.
- **Why it matters.** Azure DevOps acts on `##vso[` anywhere in a log line. GitHub Actions acts on `::cmd::` at the start of one, and this warning line starts with the attribute name. A name can't hold a space or `=`, but it can hold ESC.
- **Who's affected.** Teams that run either CI system on PRs from contributors.

The task is to find out what each platform's checkout step lets us control, then either close the route or record it as an accepted residual in an ADR.

## Out of scope
- Git calls in the repo's own scripts (done in starter T-024; `ci-pr-checks.sh` and `commit-msg` are starter T-027 and T-028).
- The inline git calls in the CI YAML (the trusted-gate block's `rev-parse`, `ls-tree` and `cat-file`, and Azure's `git fetch`). They're the same quiet commands as in `ci-pr-checks.sh`; fold them into T-027 if they need a change.

## Risks / dependencies
- The checkout step belongs to the CI platform, so a fix may only be possible on one of them. If neither can be closed, the outcome is an ADR, not code.
- An ADR 0005 edit is a `.starter/docs/` change, so it needs the full review cycle and a `unanimous-consensus:` line.
